## 本轮关键契约

1. 内核不硬编码业务角色。Profile 表达角色；tags 表达运行态或生命周期。Scope 支持 `conversationIds`、`tags`、`profileIds`：字段之间 AND、数组内 OR、缺省不限、空数组不匹配。
2. 工具声明按会话过滤，执行时再查当前会话并检查 Scope。Scope 是会话策略；不带 conversationId 的人工 HTTP/CLI 动作调用不受此策略限制，仍需 Hub 鉴权。`run_action` 和工作流动作必须带所属会话，不能借此绕过。
3. `createAsk()` 返回 `AskResult { id, status, answers }`，status 为 answered/cancelled/superseded；取消与被其他界面处理正常 resolve，answers 为 `{}`。验证、存储或宿主失败 reject。先登记 waiter，再落盘和发布；终态确认落盘后才能交付。预分配 ID 不覆盖已有审批。
4. 插件 `ctx.host.manageConversation(id)` 自动绑定该插件；删除托管会话须在 abort/清理之前返回 409 `conversation_managed_by_plugin`。停用/回滚解除管理和生命周期监听。
5. `ctx.doc(name, initial, { public: true })` 才能经 HTTP/CLI 读取并推送 `plugin.doc.updated`；私有、未声明、停用或不存在均 404。`ctx.route` 只声明 `/webhook/:id` 这类相对路径，由宿主添加插件命名空间。
6. `ConversationDetail` 直接扩展 summary，增加 `entries` / `nextCursor`。assistant 文本在 `entry.model`，不能只返回 data。输入 meta 从 CLI/HTTP 进入 `helm.input.data.meta`，传到 `turn_settled.inputs`。
7. SSE snapshot 包含 `ui` 和 `workflowRuns`。新增 entry/live/doc/workflow 事件；live.text 是累计快照、客户端替换显示。`plugin.changed` 必带该插件当前 `ui`，停用/卸载为 `[]`。
8. 模型优先级：会话显式覆盖 > Profile.model > 全局（启动参数 > HELM_MODEL > config.model）。`PATCH {model:""}` 清覆盖；切换 Profile 要重算继承模型。无模型必须显式 `model_not_configured`，不引入虚假生产模型。
9. 受管进程 Token 仅在内存有效，供 Shell 内 CLI 访问真实 Hub；剥除继承 HELM_TOKEN、统一出站脱敏，关闭后失效。CLI 登录凭据只存独立 `cli-token`（0600），不迁移 `credentials.json.cli`；环境 HELM_TOKEN 优先且短路磁盘读取。
10. spawn 元数据使用 `onResolved({conversationId?,executionId?,effectiveCwd?,worktree?})` 与 `onGateResult({ok,output})`；没有 `onCreated`。外部 executionId 带 gate 却未回报结果，必须显式 `gate_result_missing`，禁止猜本机目录或重复运行 gate。
11. 工作流 `onRunSettled` 接 `kernel.notifyWorkflowSettled`，等待插件清理后才完成 wait；运行摘要通过 provider 注入 snapshot，内核不要直接读取工作流存储布局。
12. 新 CLI：`conversations list --profile/--status`、`send --meta --wait`、`workflows run --wait`、`workflows runs`、`plugins doc`。两个 wait 映射 HTTP `?wait=1`；send 等待本次 SDK Submission 的回答，不能等待整个会话空闲或轮询。失败/中止须显式报错，CLI 非零退出。

## 实际边界
