# Herdr 总览数据与事件链路修复验收

本轮补齐 `builtin:herdr` 已有总览的数据缺口：从仅展示受管任务的 `outcome`，改为展示所配置本机 Herdr 会话中的全部窗格、真实五态、目录与归属。没有新增 Web 外壳、triggers 或附件功能。主设计文档的用户独立修改未纳入本轮。

## 行为与契约

公开文档仍通过现有鉴权接口和 CLI 读取：

```bash
pnpm helm plugins doc builtin:herdr overview --json
```

`overview` 使用新开发契约 `version: 2`，没有旧格式读取或迁移层：

- `panes` 以真实 `session.snapshot.panes` 为基表，包含人类 Agent 和普通 Shell。`agentStatus` 保留 `idle / working / blocked / done / unknown`；普通 Shell 使用官方 `unknown`，不伪造 `idle` 或状态序号。
- `stateChangeSeq` 仅来自匹配的 `AgentInfo`。`cwd / foregroundCwd / label / title / agent / agentName` 在写入 SQLite 前脱敏。
- `ownedBy: 'helm'` 要求精确匹配受管记录、冻结连接目标、tab 和 Agent 身份。其余行均为 `human`，不叠加任务 `outcome` 或审批管理字段，也不自动加入受管登记、Watchdog 探针、审批或清理。
- `stale / error` 明示快照读取或订阅故障；保留最后成功数据与采集时间。首次采集前保持 `stale: true`。成功读取快照不能自行清除订阅故障，只有真实订阅 ACK 才恢复事件流健康。
- `screen` 声明订阅 `overview` 文档；实际浏览器页面仍属于后续 Web 阶段。

## 事件与生命周期修正

真实协议验收发现并修正两处既有链路问题：Herdr 全局 `EventEnvelope` 的帧名使用 `pane_created` 等 snake_case，专用状态过滤事件使用 `pane.agent_status_changed`；订阅请求名称仍使用点号。传输边界现在正确规范化两种官方事件形状。

移动窗格只发 `pane.moved`；关闭标签页或工作区可以只发 `tab.closed / workspace.closed`。总览同时监听这些拓扑事件，不等待虚构的逐窗格关闭通知。状态事件按当前全部 pane ID 逐个订阅；窗格集合变化时先取得新流 ACK，再释放旧流，并重读快照覆盖建立过滤订阅期间的变化。

无事件的目录、seen 等变化复用现有服务端 Watchdog tick 校准，没有新增前端轮询或独立定时器。刷新采用单飞补刷；关闭水位阻止旧快照复活已关闭行。停用会取消订阅和在途读取，并等待异步工作结束，旧周期不再写文档或通知。

真实冒烟可在 Herdr 环境中复跑：

```bash
cd /root/code/helm
pnpm build
timeout 50s node scripts/herdr-overview-smoke.mjs
```

脚本仅控制自己创建的临时命名会话，保留临时日志，并在超时或信号中断时清理。没有调用真实模型、操作用户现有窗格或执行 SSH 远端验收。完整实现、测试和说明以本轮修复提交为准。
