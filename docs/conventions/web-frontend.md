# Web 前端设计系统与开发约定

编写或重构 Web 界面、新增主舞台/视图/弹窗/抽屉，或排查移动端样式与字号问题时，必须先阅读并遵守本文。

## 1. 视图形态分级与职责边界

界面按信息量与操作复杂度分为三档。选择哪一档不是审美问题，而是硬性契约：海量内容禁止进入居中模态。

### 一级主舞台（Primary Stage）

- 适用场景：会话（`conversation`）、通用视图（`screen`）、插件中心、应用中心等管理与市场类界面。
- 形态：占满中央视口，响应式多列自适应卡片网格（Marketplace Grid），顶部集成检索框、多维分类切换与实时统计。
- **严禁将海量项、多维检索、管理与市场类界面塞进居中模态弹窗**（旧 860px 居中弹窗反模式已彻底废弃）。

### 右侧深度配置抽屉（Slide-out Detail Drawer）

- 适用场景：主舞台卡片点击后的深层详情、能力透视（Tools / Actions / Hooks 清单）、动态配置表单与设置面板扩展。
- 尺寸契约：桌面端固定宽度 520px~560px，贴右侧全高展开；移动端（≤680px）自适应 100% 全宽。
- 实现契约：基于 `@helm/plugin-client` 的 Radix `Dialog` 原语封装，支持 Escape 退出、点击遮罩关闭与受管焦点圈定。

### 轻量居中模态（Centered Modal）

- 仅限轻量操作：危险二次确认、短表单创建、单一密钥/凭据录入、即时图片或 Mermaid 预览。
- 最大宽度克制在 480px~640px，避免多层嵌套卡片与臃肿滚动条。

## 2. 设计系统原语与 CSS 架构

- **严禁大面积内联样式（`style={{ ... }}`）**：除极少数动态计算的尺寸/坐标外，排版、间距与颜色一律使用设计系统原语类与 CSS 变量。
- 核心布局与表单原语：
  - 分栏结构：`.asset-modal-body` / `.modal-body-split`（两栏分屏）、`.asset-modal-list` / `.modal-sidebar`（标准 240px 侧栏）；
  - 列表项：`.list-item-btn`（标准行高与 hover/active 激活背景 `--nav-active-bg`）；
  - 平坦化区域：`.section-flat`、`.section-flat-header`、`.section-flat-title`（移除嵌套卡片）；
  - 表单网格：`.form-grid`、`.form-grid-label`（两列弹性自适应，标签支持锁图标与必填星号）；
  - 空状态：`.empty-state`（线性矢量图标 + 居中说明文本）；
  - 通用表格原语：`.helm-table-wrap` / `.table-wrap` 与 `.helm-table` / `.table`（统一 8px 10px 内边距、12.5px 字体、`border-collapse: collapse`、表头背景 `var(--bg-subtle)`、`tr:hover`、`.table-actions` 与 `.table-empty`）；
  - 插件页面与分节原语：`.screen-container`（统一内边距与纵向滚动）、`.screen-header` / `.screen-title` / `.screen-subtitle`、`.screen-section` / `.screen-section-title`；
  - 键值概览原语：`.kv-grid` / `.kv-list`（两列自适应）、`.kv-key`、`.kv-val`；
  - 提示横幅原语：`.callout`（`.callout-warn` / `.callout-error` / `.callout-ok`，统一边框、浅色背景与圆角）；
  - 加载中原语：`.loading-state`；
- **插件 client.tsx 布局原语组件（`@helm/plugin-client` 导出）**：`Screen`（页面容器+页头 title/subtitle/actions 或 header）、`ScreenSection`（分节）、`DataTable`（组合式表格外壳，统一 loading/empty）、`KvGrid`（键值概览）——上述通用结构与插件前端开发时优先使用这些组件而非手写 div+className，CSS 仅用于业务特异结构；
- **强制样式复用铁律（杜绝各车间私有复制）**：
  - **全仓所有内置插件与外部插件必须优先复用主框架设计系统原语**，严禁在插件内私自复制通用表格、通用页面布局、通用键值列表或通用提示条样式；
  - 仅限插件独有的特异性业务结构（如 Mermaid 图表缩放画布、Workflow DAG 执行图卡片、Apps 启动台卡片网格）允许在插件 client CSS 内编写专属规则；所有通用排版与组件样式必须统一收敛在主框架中，确保全平台视觉与交互风格绝对统一。

### Radix UI 唯一无头交互原语底座

凡涉及浮层、对话框、下拉选择、标签页、气泡提示等复杂交互组件，**必须使用已有的 Radix 封装**。共享实现位于 `packages/plugin-client/src/ui/`，通过 `@helm/plugin-client` 公开；Web 专有组件位于 `packages/web/src/ui/`。严禁使用原生控件或引入第三方重量级 UI 库：

- **弹窗与抽屉**：`Dialog` 使用 SDK 封装；Web 危险确认使用 `AlertDialog`；
- **下拉选择**：全仓严禁原生 `<select>`，统一使用 SDK 的 `Select` / `MultiSelect`（高度 30px，字号 12px，无障碍 combobox 契约）；
- **下拉菜单与气泡**：Web 操作菜单使用 `DropdownMenu`，共享气泡使用 SDK 的 `Popover`；
- **标签页**：分段控制与视图切换使用 SDK 的 `Tabs` / `SegmentedControl`；
- **轻量提示**：Web 使用 `Tooltip`；
- **开关与勾选**：使用 SDK 的 `Switch` / `Checkbox`。

SDK 不导入 Web store、路由或渲染实现。`HelmStoreProvider` 通过 `PluginClientHostContext` 注入真实数据与宿主能力；订阅、详情加载等稳定函数直接复用原函数引用，避免快照更新引起退订重连。插件与宿主必须共享同一个 SDK 上下文实例。

**严禁手写简陋交互浮层**：不得用原生 `div` + `position: absolute` + 随意 `onClick` 拼凑浮层，杜绝缺乏键盘无障碍（WAI-ARIA）、Focus Trap 焦点逃逸、Escape 无法退出与遮罩穿透问题。

**SSR 与单元测试防破裂契约**：所有 Radix 封装原语必须保证在 Node / SSR（`renderToString`）测试环境下可用——统一以 `typeof window === 'undefined'` 或 `inline` 属性降级直接渲染 children，避免 Portal 导致测试断言拿到空 DOM。

## 3. 字体层次与移动端响应式规范

### 极简紧凑的字体阶梯

| 用途 | 字号 |
| :--- | :--- |
| 工作台主文本与输入框（侧栏、顶栏、表单、按钮、抽屉） | 13px / 14px |
| 会话阅读档：AI 正文、人类提问胶囊与 Composer 输入框 | 15px |
| 会话内代码块与工具输出代码 | 13px（行内代码 0.88em 按正文比例） |
| 思考过程正文（展开体） | 13.5px |
| 辅助文本与表单标签 | 12px |
| 状态徽章与胶囊计数 | 11px |
| 面板与分组标题 | 13px / 14px（粗体） |
| 顶栏与主舞台大标题 | 15px / 16px |

- **会话 Markdown 排版限定在回合容器 `.msg-ai-block` 内**：正文 15px / 行高 1.65，标题阶梯 h1 1.35em / h2 1.2em / h3 1.08em / h4 1em，相邻列表项间距 3px。思考正文为 13.5px / 行高 1.6，标题为 13.5px；会话代码块（含回合外的交接与精简摘要）为 13px。技能阅读器（13.5px）、产物预览等共享渲染器的上下文沿用基础字号。
- **提问与输入字号一致**：人类提问胶囊和 Composer 输入框（含智能体待命页）均为 15px / 行高 1.55，桌面、移动与分屏使用相同字号。

### 移动端与分屏字号铁律

- 严禁任何输入框（`<input>` / `<textarea>`）在移动端或分屏宽度下字号突兀放大或失真，必须保持与全局紧凑层次一致；
- 通过精确的 CSS 规则覆盖，消除平台默认的点击放大渲染异常。

### 移动端响应式断点（`@media (max-width: 680px)`）

- 弹窗与抽屉必须 `width: 100vw; max-width: 100vw; left: 0; right: 0;` 自适应全宽；
- 头部容器必须配置 `flex-wrap: wrap`，标题截断保底，右上角关闭按钮绝对可用；
- 操作按钮组折行到底部或自适应排列，禁止溢出视口产生横向滚动条。

## 4. UI 极简零 Emoji 铁律

Web 界面与所有插件 UI 遵循极简克制风格，**严禁在界面文案、左栏导航项、分组标题、按钮、状态徽章或卡片中使用任何 Emoji 表情图标**。图标统一使用 `lucide-react` 线性矢量图标（经 `HelmIcon` 组件）或纯文本排版。

## 5. 组件生命周期与 Fast Refresh

- `.tsx` 文件**只导出 React 组件与 TypeScript 类型**；
- 纯数据转换、枚举映射、排序与过滤纯函数必须剥离到单独的 `*-model.ts` 文件；
- 异步数据加载（配置读取、远程状态等）必须引入代数竞争保护（`loadGeneration.current += 1`），避免切换目标后旧请求结果反向覆盖新状态。

## 6. 会话工具展示

- 常规工具保留 26px 单行轨迹与 `StepGroup` 折叠；专属展开体属于宿主展示，不注册为插件 `tool.view`，不改变业务卡片的折叠豁免。已有插件视图优先。
- 展开体按工具语义呈现：`edit` 展示变更，`write` 展示写入源码，`read` 展示读取结果，`bash` 展示命令与输出尾部。提供原始数据入口，保留完整参数、输出与结构化结果的核对能力。
- 待执行、成功、失败与未知状态必须如实区分。入参中的 `oldText / newText` 只能形成片段对比，不代表已经落盘，不附会文件行号；成功后的文件差异只消费内核实际执行结果，禁止重新读取当前文件冒充历史快照。失败不等于没有磁盘副作用（例如写入后产物登记失败），失败态只标明执行失败与请求内容，不承诺“未写入”或“未应用”。
- `edit` 结果遵循 `@helm/protocol` 的 `EditToolResult` 与 `EDIT_TOOL_RESULT_SCHEMA`。内核在目标文件互斥窗口内生成真实行号与上下文，写入成功后返回；Web 在消费边界校验，缺失或非法数据明确提示。
- 行级差异使用淡色语义背景；单行替换可额外标出词级变化。差异行号不可参与源码选择，移动端与分屏优先采用统一差异视图，滚动限制在代码区域。
- 内容折叠与数据截断须分清：前者可展开已有全文，后者明确说明部分数据未传回，不提供虚假的“展开全部”。差异计算与展示均须有预算；内核先脱敏再限制文本大小，脱敏影响行号映射时省略差异正文并明确标记未完整展示。

## 7. 表单真实性与整体替换保存契约

- **真实编辑入口铁律（杜绝假入口）**：凡渲染为可编辑的表单控件，其保存链路必须真实持久化该字段；无法落盘的配置一律只读展示并指明真实修改路径，禁止「可编辑却保存无效」的假入口。保存成功提示必须与实际持久化范围一致，不得宣称未发生的写入。
  - 按来源分流（模型中心供应商抽屉为范例）：插件网关（`pluginId` 存在，如 `builtin:magpie`）的服务端点与 API 密钥由所属插件的配置项管理——只读展示「由插件 X 的配置管理」并指引插件中心，不写入内核凭据库；内置供应商端点为固定值，只读标注；仅自定义网关（providers.json）端点可编辑，保存经 `PUT /api/providers` 只更新该条 `baseUrl`，其余网关与字段原样保留。
  - 必填字段清空保存必须显式报错（如自定义网关服务端点），不得静默保留旧值冒充保存成功。
- **整体替换（PUT）保存契约**：抽屉表单保存以最近一次完整详情为基底，仅覆写表单暴露字段，未暴露字段原样回传，不因表单裁剪而丢。可选绑定字段显式表达空值语义：非空写入、置空显式删除键，防止详情基底在整体替换中复活旧绑定（范例：Profile 编辑抽屉「默认节点」`nodeId`——置空即解绑，必须从 payload 显式删除）。
- **绑定类 Select 选项集**：节点等资源绑定下拉提供「未绑定」空值项、资源列表全量（本机/在线/离线标注）与未知值回退项；既有绑定不在列表中时只读呈现原值并标注未知，不得静默清空或伪装成合法选项。
