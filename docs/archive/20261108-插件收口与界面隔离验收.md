# 插件收口与界面隔离验收

本轮补齐设计核查发现的四项缺口，并处理“插件未启用仍显示 Herdr 配置”等界面隔离问题。实现已集成到主树；最后的代码修正提交为 `42152f6f`。验证使用当时的完整工作树，包含主树同时推进的模型、思考与时间线修改；这些并行修改保持独立，没有被本轮提交收走。

## 交付行为

- **外部插件加载**：启动扫描 `<dataDir>/plugins/`，读取 `plugin.json.main` 或约定的 `index.mjs / index.js / plugin.mjs / plugin.js`。模块导出遵循 `PluginDefinition.definePlugin`；默认停用，持久启用状态跨重启恢复。纯数据目录跳过；损坏清单、入口缺失、文件读取失败、越界入口与重复 ID 明确报错。客户端根目录缺省为插件目录，可经原有 HTTP/CLI 接口编译获取。插件是可信进程内代码，停用不构成代码沙箱。
- **Web 生产托管**：Hub 默认探测已构建的 `packages/web/dist`；支持 `startHub({ webDistDir })` 与 `HELM_WEB_DIST_DIR` 指定目录，`false` 禁用。GET/HEAD 提供静态资源，无扩展名的 SPA 路由回退至 `index.html`；缺失资源和越界请求返回 404。API 保留鉴权与 JSON 错误契约。
- **跨节点派工**：`dispatch_worker` 接受 `nodeId` 与跨平台绝对路径 `cwd`，CLI 自动提供 `--node-id`、`--cwd`，与 HTTP、Tool、Workflow 共用 Schema。
- **产物源码预览**：Markdown 源码与代码类产物复用语法高亮组件；文件后缀优先，MIME 补充，未知语言按普通代码显示。
- **插件界面隔离**：未启用 Herdr 时，普通 Profile 不显示 Herdr 徽章和运行时表单，基础页签显示“基础信息”。已配置的外部运行时保留，用户可以显式清除；其他运行时不会被当成 Herdr 修改。登录提示使用通用节点文案。
- **资产和会话归属**：Profile/Skill 使用明确的 `managedByPlugin` 控制可见性，常驻专属 Profile 使用 `humanSelectable: false` 排除出新建对话列表。归属字段经过 Web 保存、HTTP 校验、CLI 输入与文件持久化完整保留。会话摘要和 SSE 投射权威 `ownedBy`，“我的对话”排除托管会话与派生子会话。未按角色名称或标签猜测归属，也未迁移、回填或删除既有用户资产。
- **停用与删除竞态**：技能查看器在所属插件停用后清除选中内容并作废在途读取；删除会话后，迟到的 tracker 摘要不再发布 upsert。归属读取失败不能伪造 human 摘要。

## 验收边界

- 使用独立临时数据目录与系统分配端口，没有替换用户的开发服务或修改旧系统运行数据。
- 浏览器的 Herdr 接口为明确的测试夹具，仅用于验证插件启停与配置显示；没有操作真实终端窗格或调用真实模型。
- Windows 盘符与 UNC 验证的是校验、参数传递和协议行为，不代表 Windows 实机验收。
- 既有资产保持原样；没有归属标记的文件继续按普通用户资产处理，不因同名而隐藏或改写。
- 构建仍有已有的大 chunk 提示；构建和型检均成功。
