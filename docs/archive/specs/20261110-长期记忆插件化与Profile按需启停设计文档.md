# 长期记忆插件化与 Profile 按需启停设计文档

## 背景

Helm 原将全部 Profile 的角色认知装配能力（`SYSTEM.md` 注入、`MEMORY.md` 注入、`<available_skills>` 技能目录、`update_memory` / `load_skill` 工具）耦合在一个名为 `builtin:assistant`（`locked: true`）的插件中，并把长期记忆的存储接口硬编码在公共协议包与内核服务层。这产生四处问题：

1. **机制与实例概念错位**：`assistant` 只是默认预置的一个具体 Profile 实例，但驱动全系统所有 Profile（含 `coder`、`superagent`、`watchdog` 与用户自定义角色）运转的底层插件却被命名为 `builtin:assistant`，注入其他角色的 Prompt Section ID 也带 `assistant.` 前缀。
2. **静态角色定义与运行期记忆状态耦合**：Profile（`profile.json` + `SYSTEM.md` + `skills`）是静态角色声明，长期记忆（`MEMORY.md`）是模型运行期高频改写的状态子系统。两者绑死在同一个 `locked: true` 插件中，用户既无法按单个 Profile 关闭记忆，也无法全局停用记忆能力。
3. **公共包与内核层残留记忆代码**：`@helm/protocol` 的 `Profile` 接口含 `memory?: string`；`ProfileService` 含 `getMemory` / `updateMemory` / `MAX_MEMORY_CHARS`；HTTP 路由、CLI 与 Web 角色编辑抽屉都硬编码 memory 读写，违背「记忆代码归口记忆插件、内核与公共包零记忆依赖」的分层原则。
4. **默认提示词硬编码**：内核 `SYSTEM_DEFAULT` 硬编码 `update_memory` 使用指令；插件停用后该指令仍残留在系统提示中，形成幻影能力。

同分支一并移除「初始会话 `#1` 不可删除」的特殊设计：普通人类会话不因绑定 `assistant` 或占用 id 1 而受保护，通用保护仅保留插件管理权（`409 conversation_managed_by_plugin`）与归属权红线（human 会话严禁自动按键/中止）。

非目标：不改变磁盘记忆文件 `<dataDir>/profiles/<id>/MEMORY.md` 的物理路径与 64,000 字符上限；关闭单 Profile 记忆或停用记忆插件不删除磁盘已有文件；默认 `assistant` Profile 本身仍不可删除（本轮仅移除会话级豁免）。

建议分支：`refactor/profile-memory`。

## 整体设计

改造横跨 `@helm/protocol`、`@helm/kernel`、`@helm/web`、`@helm/cli` 四个包，保持依赖方向 `web` / `cli` → `protocol` ← `kernel` 不变，protocol 与内核核心服务层对记忆零感知。

```mermaid
flowchart TB
    subgraph Protocol["@helm/protocol（零记忆字段）"]
        ProfileContract["Profile（id/name/model/cwd/skills/system…）"]
        SlotContract["PROFILE_DETAIL_SECTION_SLOT + ProfileDetailSlotProps<br/>（profileId/isNew/disabled）"]
    end

    subgraph KernelCore["@helm/kernel 核心层（零记忆逻辑）"]
        ProfileSvc["ProfileService（profile.json + SYSTEM.md）"]
        Host["PluginHost：hooks / ctx.action / ctx.tool / ctx.doc / ctx.ui.slot"]
    end

    subgraph BuiltinPlugins["packages/kernel/src/builtin-plugins/"]
        ProfilePlugin["builtin:profile（locked，角色与技能底座）<br/>SYSTEM.md 注入 · 技能目录 · load_skill · 种子自举"]
        MemoryPlugin["builtin:memory（默认启用，可停用）<br/>MemoryStore · 单 Profile 开关 · update_memory · 三动作"]
    end

    subgraph WebCli["@helm/web 与 @helm/cli"]
        Drawer["ProfileDetailDrawer：基础表单 + PluginSlot"]
        MemorySlotUi["memory client：单 Profile 开关与编辑器"]
        DynamicCli["helm memory get / set / configure（动作自动映射）"]
    end

    WebCli --> Protocol
    KernelCore --> Protocol
    ProfilePlugin --> ProfileSvc
    ProfilePlugin --> Host
    MemoryPlugin --> Host
    MemoryPlugin -.ctx.ui.slot.-> Drawer
    Drawer --> MemorySlotUi
    MemorySlotUi --invokeAction--> MemoryPlugin
    DynamicCli --> MemoryPlugin
```

职责划分：

- **`ProfileService`**：仅管理 `profile.json` 与 `SYSTEM.md`，不含任何 `MEMORY.md` 接口；`fs-atomic` 通用原语（`withFileLock` / `atomicWriteFile` / `readTextFile`）保留在内核服务层供各插件共用。
- **`builtin:profile`（locked: true）**：为全部会话按 `profileId` 注入 `SYSTEM.md`（`profile.system`）与可用技能目录（`profile.skills`），提供 `load_skill` 工具，自举默认 `assistant` Profile 与系统技能 `helm-cli`，并在左栏注册 `conversation:profile:assistant` 站位导航。
- **`builtin:memory`（locked: false，默认启用）**：承载全部长期记忆能力——存储、注入、工具、动作与 Web 插槽，详见下文。

### 初始会话与导航

初始入口会话由 SDK 保留的 root 会话（id 1）承载，语义上是一个普通 assistant 人类会话：

- 首次启动经 `harness.root()` 播种，获得 id 1，绑定 `assistant` Profile，无任何 id 级删除豁免；
- 用户删除后，Helm tombstone 生效：重启时初始化流程检测到已删除即跳过镜像与观察，不复活、不补种（SDK 存储中保留的 root 行只是内部机制，不构成产品不变量）；
- Web 左栏 assistant 站位指向 Profile（`conversation:profile:assistant`）而非某一具体会话：该 Profile 会话全部删除后站位仍在，点击可新建会话；无显式目标的 trigger 投递见下文。

### 会话删除与缺省 trigger 投递

- **删除保护**：仅插件管理权（`ctx.host.manageConversation`，`409 conversation_managed_by_plugin`）与归属权（`ownedBy`）是通用保护；HTTP / CLI 删除初始会话与其他普通会话同权返回成功。
- **缺省 trigger 靶点**：无 `targetConversationId` 的信封（trigger 钩子链处理后仍未定向）投递到 assistant Profile 下最新的无父链 human-owned 会话；归属权读取权威 ownership 登记，不从 tags 或摘要投影推断。没有候选时按需新建，同进程并发共享一次在途创建；Promise 完成即清理，不缓存会话 ID，创建失败后可重试。
- **显式 trigger 靶点**：在任何 trigger hook 运行前校验原始显式目标是否存在；已删除目标以 `404 not_found` 上抛，不能被 ThreadKey 订阅的 transform/handled 掩盖。合法目标仍遵循既有插件路由策略。
- **Web 缺省位置**：地址栏空 Hash 与主屏会话删除后的回退目标为角色中心（`#/profiles`，无会话依赖），支持零会话空状态与新建入口。分屏会话删除只关闭该分屏，抽屉会话删除只关闭对应抽屉；统一由删除事件对当前导航状态做条件更新，迟到的删除响应不覆盖用户已切换的新位置。
- **工作流运行目标**：新 run 必须有显式 `conversationId` 或调用会话上下文（CLI 使用 `--current`）；缺少目标以 `400 validation_error` 拒绝，不改投最新会话。`resumeFromRunId` 未指定目标时沿用原 run 会话，目标不一致或已删除时显式拒绝。

## 详细设计

### 记忆存储与 64k 防线

`MemoryStore`（`builtin-plugins/memory/store.ts`）自管 `<dataDir>/profiles/<profileId>/MEMORY.md`：

- 复用内核 `fs-atomic` 原语：进程内按真实路径串行化（文件锁）、temp+rename 原子落盘，`AssetWatcher` 实时感知且绝不见半截内容；
- `MAX_MEMORY_CHARS = 64_000` 上限在**文件锁内对合并后的最终内容**统一强制：并发 `append` 不可能各自预读旧值检查通过后叠加突破上限；超限显式抛 `400 memory_limit_exceeded`（提示 replace 精简），不写半截文件；
- 公开写入接口（`updateMemory(profileId, text, mode)`）不提供任何上限参数——所有调用路径（`update_memory` 工具、`set` 动作、`configure` 携带 text）走同一强制防线，无绕过入口；
- 存量超限（外部手改文件绕过写入防线）：注入时截断并附显式说明，不静默截断、不修改源文件。

### 插件私有状态（磁盘是全文唯一权威）

`MEMORY.md` 全文不进任何公共文档、不进全局首帧或 SSE 广播，避免双写全文与全局广播写放大。插件私有 `ctx.doc('state')`（state.sqlite 持久化）只保存两份紧凑状态：

| 字段 | 语义 |
| --- | --- |
| `disabledProfiles: string[]` | 已关闭长期记忆的 Profile ID 列表（不在列表中默认开启），跨重启保持 |
| `initializedProfiles: string[]` | 已初始化过 MEMORY.md 的 Profile ID 列表，跨重启区分「从未初始化」与「已初始化后被删」 |

Web 端不订阅公共文档，经 `get` 动作按需读取当前 Profile 的内容与开关，并显示服务端真实错误。Profile 删除后以相同 ID 重建时，插件私有的开关与初始化状态继续按该 ID 生效；本设计不在 Profile 删除时清理这些状态。

### before_turn 注入与工具剥离

开启记忆的会话在每回合获得：

| 段落 ID | 触发条件 | 内容 |
| --- | --- | --- |
| `memory.content` | MEMORY.md 非空白 | `<memory>` 包裹全文 + `update_memory` 用法提示 |
| `memory.guide` | MEMORY.md 空白（合法态） | 仅 `update_memory` 用法提示，无告警 |
| `memory.assets-missing` | 已初始化后被外部删除 | 显式警告段落 + 人类侧 warning 通知（按 profileId 独立去重），不重建 |

单 Profile 关闭时：不读取记忆文件、不注入任何记忆段落，并从本回合工具表中剥离 `update_memory`。`update_memory` 的 `execute` 入口同样复核开关，关闭时抛 `403 memory_disabled_for_profile`，本次调用不写盘。开关影响后续调用与回合，不取消已经开始的写入或回合。

用法指引（「用 `update_memory` 保存稳定的用户偏好与约定」）由本插件动态注入：内核 `SYSTEM_DEFAULT` 不再硬编码该指令，插件停用后指引随之消失，不留幻影能力。

### 初始化与缺失判定

- **惰性初始化**：从未初始化的合法 Profile 首次需要记忆时（before_turn 读取发现文件不存在且不在 `initializedProfiles`），创建默认骨架文件（`# Memory` 标题非空白，注入 `memory.content`）并标记初始化；
- **删除缺失告警**：`initializedProfiles` 含该 Profile 但文件不存在，判定为已初始化后被外部删除——发 warning 通知 + 注入 `memory.assets-missing`，绝不静默重建掩盖丢失；文件恢复或经 `update_memory` / `set` 显式写入后自愈；
- 两份判定均基于持久化标记，跨重启成立；其他插件（如 `builtin:superagent`）的自举只补齐 `profile.json` / `SYSTEM.md`，绝不创建或补回记忆文件。

### 动作契约（五端复用）

三个 `ctx.action` 自动映射为 HTTP `POST /api/actions/builtin:memory/<action>`、CLI `helm memory <action>`（支持 `--json` 与通用 `--current` 感知）、Agent Tool 与 Web `invokeAction`：

| 动作 | 输入要点 | 行为要点 |
| --- | --- | --- |
| `get` | `profileId` 可选 | Profile 不存在 `404 profile_not_found`；返回 `{ profileId, enabled, content, initialized }`，文件缺失如实返回空串 |
| `set` | `text` 必填；`profileId` 与 `mode` 可选，mode 为 `append`/`replace`（缺省 replace） | 单 Profile 已关闭 `403`；超限 `400 memory_limit_exceeded` |
| `configure` | `enabled` 必填；`profileId` 与 `text` 可选 | 携带 text 时先写入成功再提交开关（不留半配置）；开启且未初始化时惰性创建文件；开关跨重启持久 |

三者都按同一优先级解析目标：显式 `profileId` 优先；省略时使用 `context.conversationId` 的 Profile（HTTP body 的 `conversationId` 或 CLI `--current` 提供上下文）；二者皆无以 `400 validation_error` 拒绝。显式无效 Profile 或无效会话上下文不会回退到 assistant 或其他 Profile。

### Web 单 Profile 插槽

`ProfileDetailDrawer` 在原记忆区块位置挂载通用 `<PluginSlot ownerPluginId="builtin:profile" name={PROFILE_DETAIL_SECTION_SLOT} slotProps={{ profileId, isNew, disabled }} />`，宿主不硬编码任何记忆业务。`builtin:memory` 的 client 组件经 `ctx.ui.slot` 注入：

- 单 Profile「启用长期记忆」开关（即时生效，经 `configure`）；
- `MEMORY.md` 编辑器与「保存记忆」按钮（经 `set`，内容独立保存，不随「取消角色编辑」回滚）；
- 新建尚未落盘的 Profile 只提示先创建角色，再配置记忆；
- 加载、开关与保存共享当前 Profile 与请求代数守卫；切换/卸载使旧结果、错误与 finally 失效；宿主 context 重建不触发真实 Profile 的状态重置；
- 保存捕获 `submittedText`，响应只更新已保存基线；保存期间继续输入时保留本地续打，不以旧 `fresh.content` 覆盖；加载失败不伪装为已关闭状态；
- 插件停用后插槽贡献即时消失，宿主表单不受影响。

### 内核与公共包清理

- `@helm/protocol`：`Profile` 接口删除 `memory` 字段；HTTP 边界（`parseProfileBody` 白名单）对携带 `memory` 的请求显式 `400` 拒绝，不做兼容读取；服务层静默剥离未知键（历史行为不变）；
- `ProfileService`：删除 `getMemory` / `updateMemory` / `MAX_MEMORY_CHARS` / `MEMORY_DEFAULT`；`ensureDefault` 与 `save` 不再创建 `MEMORY.md`；
- CLI `profiles` 命令删除 `--memory` / `--memory-file`，记忆操作完全由 `helm memory` 动态命令承担；
- `ROOT_CONVERSATION_ID` 公共契约删除：产品逻辑不依赖固定会话 ID；组合入口（`app.ts`）注册 `createProfilePlugin` 与 `createMemoryPlugin`，内核核心服务不反向 import 记忆模块。

## 发布

普通可逆代码发布，无 Schema 迁移与数据回填：

- 开发阶段不兼容不迁移：旧 `builtin:assistant` 插件 ID、旧 `Profile.memory` 请求字段与旧 `root_conversation_protected` 错误码一律不保留兼容层；
- 单 Profile 启停经 Web 开关或 `helm memory configure --profile-id <id> --enabled=false`，磁盘 `MEMORY.md` 保留，重新开启即恢复；
- 全局启停经 `helm plugins disable builtin:memory` / `enable`，私有开关状态与磁盘文件均保留；
- 本项目开发阶段不提供新旧插件 ID 与配置的数据迁移；版本回退不能恢复已删会话或自动转换新版插件私有状态。需要回退时先停止运行任务并备份本项目数据，按对应版本重建开发数据；磁盘记忆文件需人工核对后恢复，不承诺旧版本可直接读取新状态。

## 测试

自动化测试（`packages/kernel/test/`）覆盖的关键行为：

| 场景 | 验证内容 |
| --- | --- |
| 默认协同（`core.integration` 集成 1） | `createHelm` 组合下 `builtin:profile`（locked）与 `builtin:memory`（默认启用）并存；`profile.system` / `profile.skills` / `memory.content` 真实进入模型请求；`update_memory` 跨回合持久 |
| 单 Profile 启停隔离（`memory-plugin`） | 关闭 coder 不影响 assistant；关闭时 `set` / `update_memory` 均 `403`；重新开启后可写 |
| before_turn 守卫（`memory-plugin`） | 关闭时不读文件（删文件也无告警）、不注入段落、剥离工具 |
| 惰性初始化 / 空白合法 / 删除告警（`memory-plugin`、`plugins-fixes`） | 从未初始化首回合创建默认文件不误报；空白文件注入 `memory.guide` 无告警；已初始化后删除注入 `memory.assets-missing` + 人类告警且不重建；恢复后自愈 |
| 私有状态跨重启（`memory-plugin` 真实 createHelm） | 关闭、重新开启、初始化标记跨重启保持；磁盘全文不受 Profile 保存影响 |
| 64k 防线（`memory-plugin`、`plugins-rollback`、`services`） | append 累计与 replace 直写双路径超限显式拒绝；跨实例并发 append 不叠加突破；无绕过上限参数；原子写被 watcher 实时捕获 |
| 动作目标与端到端（`memory-plugin`、`core.integration`） | `get` / `set` / `configure` 可省略 profileId 并从真实会话上下文取 Profile；显式值优先、无目标 `400`、失效目标 `404`；真实 CLI↔Hub `helm memory … --json --current` 与 HTTP 同权 |
| 全局停用（`memory-plugin`） | `update_memory` 卸载（`unknown_tool`）、动作 `404`；其他插件 SYSTEM 注入不受影响；重新启用恢复 |
| superagent 记忆归属（`superagent`） | memory 停用时启用 superagent 不创建 MEMORY.md；已初始化文件被删后整体重启与 superagent 重新自举均不补回，memory 检测仍发缺失告警 |
| 初始会话删除（`initial-conversation`） | 内核 / HTTP 删除成功；删后重启不复活、不补种；零会话下可新建；`manageConversation` 保护仍 `409` |
| 缺省 trigger（`runtime`、`initial-conversation`、`superagent.integration`） | 最新 bot/helm assistant 不压过 human-owned 顶层会话；删空后并发触发只建一个；已删显式目标 + 有效 ThreadKey 订阅仍 `404`，Worker 不收输入 |
| 工作流目标（`workflow`、`core.integration`） | 删除初始会话后无目标 run 明确 `400`；CLI `--current`、显式目标与工具 context 正常；resume 使用原 run 目标且拒绝改投 |
| 删除导航（`conversation-delete-navigation`） | 真实组件点击删除：主 A+分屏 B 删除 B 保 A、抽屉删除只关抽屉、主屏删除回角色中心、等待中切换位置不被旧响应打断 |
| 记忆编辑竞态（`memory-client-interactions`） | 真实客户端编译产物 + deferred Promise 覆盖 A 保存/toggle 中切 B、保存续打、context 重建、晚失败与卸载失效 |
| Web 插槽（`profile-center`） | 插件贡献存在时经 `PluginSlot` 渲染单 Profile 记忆区块并收到 `profileId` props；无贡献时不渲染（宿主零硬编码） |
| 旧字段拒绝（`http`、`profile-binding`） | HTTP PUT 携带 `memory` 显式 `400`；Profile 保存不触碰磁盘 MEMORY.md |
